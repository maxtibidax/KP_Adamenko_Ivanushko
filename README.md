# Курсовой проект: кейтеринг на Symfony и PostgreSQL

## Запуск

Из-за кириллицы и пробелов в пути лучше задавать имя Docker Compose проекта явно:

```powershell
$env:COMPOSE_PROJECT_NAME='course_catering'
docker compose up -d --build
```

Приложение откроется по адресу:

```text
http://localhost:8080
```

pgAdmin для просмотра базы откроется по адресу:

```text
http://localhost:5050
```

PostgreSQL доступен на `localhost:5432`, база `course_db`, пользователь `course_user`, пароль `course_password`.
В pgAdmin сервер `Course PostgreSQL` уже добавлен. Если попросит пароль от базы, введите `course_password`.

## Если нужно пересоздать базу

Init-скрипты PostgreSQL выполняются только при первом создании volume. Для полного сброса:

```powershell
$env:COMPOSE_PROJECT_NAME='course_catering'
docker compose down -v
docker compose up -d --build
```

## Учетные записи по умолчанию

| Логин    | Пароль   | Роль           | Описание                |
|----------|----------|----------------|-------------------------|
| admin    | admin    | ROLE_ADMIN     | Администратор системы   |
| manager  | manager  | ROLE_MANAGER   | Менеджер                |

Новые пользователи могут зарегистрироваться самостоятельно через страницу `/register`.

## Что реализовано

- функциональное меню: панель, банкетные заказы, склад и поставки, отчеты;
- CRUD-страницы клиентов и меню/блюд;
- общий CRUD для менеджеров, поставщиков и продуктов;
- просмотр заказов с фильтрами и пагинацией;
- сортировка таблиц заказов и склада по заголовкам колонок;
- inline-редактирование статуса и предоплаты;
- редактирование заказа в модальном окне;
- выпадающие списки клиентов, менеджеров, блюд, поставщиков и продуктов;
- календарные поля дат, чекбокс фильтра низких остатков;
- создание заказа через хранимую процедуру `create_complex_order_full`;
- отмена заказа через хранимую процедуру `cancel_order_logic`;
- триггеры для категории блюда, прибыли, проверки даты, оплаты и журнала операций;
- триггеры для автоматического пополнения склада по полученным заявкам поставщикам;
- отчет по заказам с отбором по периоду, статусу и типу мероприятия;
- отчет по прибыльности блюд;
- отчет по складу и поставкам;
- экспорт отчетов в PDF через `dompdf/dompdf` (с корректным отображением кириллицы и SVG-диаграмм);
- экспорт отчетов в Excel через `phpoffice/phpspreadsheet` (с диаграммами, не перекрывающими данные);
- регистрация и авторизация пользователей через базу данных (`app_user`);
- адаптивный интерфейс для экранов от мобильных до десктопных (3 контрольных точки + ноутбуки);
- пользовательские представления (VIEW): `v_active_orders_overview`, `v_stock_with_supply_info`;
- расширенный набор вторичных индексов для оптимизации запросов;
- скрытие технических идентификаторов в интерфейсе (человекочитаемые подписи, ФИО вместо ID);
- ролевая модель: ROLE_ADMIN (удаление клиентов, блюд, рецептов), ROLE_MANAGER, ROLE_USER.

SQL-схема лежит в `docker/postgres/init/01_schema.sql`.
Дополнительные демо-данные — в `docker/postgres/init/02_seed_extra.sql`.
